# Personnel contact and emergency fields

Deployed October 20, 2026 after explicit user authorization. The personnel_contacts migration and subsequent intake extensions are applied to live Supabase. No real personnel contact values were changed.

Personnel profiles now have a separate Contact & emergency information section with email, home address line 1, home address line 2, city, state, ZIP/postal code, emergency contact full name and emergency contact phone number. All fields are optional. Postal codes and phones remain text, including leading zeroes, extensions and international formats. Saving and clearing validate trimmed values and field lengths. Email format is validated when present.

Contacts are stored separately in private.personnel_contacts, not in public.people or the directory's bulk payload. Verified theater administrators (including the platform owner), Stage Managers, Assistant Stage Managers and Company Managers can read and update them. Stage management roles also require effective Stage edit permission and an active membership. Generic personnel edit permission does not grant contact access. Browser UI gating and the database enforce the same scope. RPCs determine theater from the selected person rather than accepting a caller-selected theater. Anonymous access, direct private-table access and cross-theater access are denied.

The invoker RPC wrappers call private, bounded definer functions following the existing settings pattern. Optimistic revision checks reject stale saves. Metadata records the actor and change time; general settings history records the action without copying contact values. No sample contact records are seeded, no user-account email is changed, and no contact values are logged or added to search/filter indexes or credit listings.

Validation: all 26 unit tests passed, including field normalization/lengths/email, leading-zero postal codes and client role gating. Local PGlite PostgreSQL ran the actual new migration and existing authorization helper definitions: create/read/update/clear, stale writes, invalid values, unknown-field rejection, cross-theater denial, each allowed/disallowed role, explicit stage denial, suspended/unverified denial, direct table denial, anonymous function denial and absent contact columns in public.people. Browser fixture verified profile placement, all eight form inputs, save and reload with fictional values. A later browser confirmation prompt stalled the automation; the complete phone-layout/unsaved-dialog browser check was not completed. The temporary fixture was removed before the final build. New modules pass targeted lint; the final production build uses Webpack because the environment blocks the default Turbopack worker.
